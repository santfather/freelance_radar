# Freelance Radar — Roadmap

## Текущее состояние ✅
- Локальное веб-приложение (FastAPI + SQLite)
- Скраперы: Zleca, Useme, WorkConnect (≈50 заказов)
- Ollama LLM-анализ каждого заказа (TAKE / SKIP + причина)
- Фильтрация по категориям и вердикту

---

## Фаза 1 — Telegram-бот (следующий шаг)

Утром не открывать браузер — бот сам присылает дайджест.

**Что делает бот:**
- В 8:00 автоматически парсит площадки и присылает только TAKE-заказы
- Каждая карточка — название, бюджет, описание, кнопка «Открыть»
- Команды:
  - `/refresh` — запустить парсинг прямо сейчас
  - `/today` — показать все заказы за сегодня
  - `/take` — только рекомендованные
  - `/stats` — статистика (всего / проанализировано / TAKE)

**Стек:** `aiogram 3` (async Telegram bot framework) + APScheduler для cron

**Файлы которые появятся:**
```
freelance-radar/
├── bot/
│   ├── __init__.py
│   ├── main.py          # точка входа бота
│   ├── handlers.py      # команды и колбэки
│   └── scheduler.py     # утренний крон 8:00
└── .env                 # + TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
```

## Фаза 3 — Деплой на Vercel

Vercel — только для фронтенда. Бэкенд + БД — отдельные сервисы.

### Архитектура после деплоя

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│   Vercel        │────▶│  Railway / Render │────▶│  Neon Postgres  │
│   Next.js UI    │     │  FastAPI backend  │     │  (free tier)    │
│   (бесплатно)   │     │  (free tier)      │     │                 │
└─────────────────┘     └──────────────────┘     └─────────────────┘
                                │
                                ▼
                        ┌──────────────────┐
                        │  Groq API        │
                        │  (LLM анализ)    │
                        │  вместо Ollama   │
                        │  llama3-70b free │
                        └──────────────────┘
```

**Что меняется при деплое:**

| Компонент | Сейчас (локально) | После деплоя |
|-----------|-------------------|--------------|
| UI | FastAPI + HTML | Next.js на Vercel |
| БД | SQLite (`radar.db`) | Neon Postgres (free 0.5GB) |
| LLM | Ollama (локальный) | Groq API (llama3-70b, бесплатно) |
| Хостинг API | localhost | Railway / Render (free) |
| Расписание | manual | Vercel Cron / APScheduler |

**Почему Groq а не Ollama в проде:**
- Groq даёт бесплатный tier: 14,400 запросов/день (для нас хватит с запасом)
- `llama3-70b` на Groq быстрее чем `qwen2.5:14b` локально
- Не нужен собственный сервер с GPU

**Шаги деплоя:**
1. Перевести фронт на Next.js (компоненты из текущего HTML)
2. Мигрировать SQLite → Neon Postgres (одна команда через `alembic`)
3. Заменить `httpx` Ollama вызовы на `groq` SDK (5 строк кода)
4. Задеплоить API на Railway (push → auto-deploy)
5. Задеплоить UI на Vercel (push → auto-deploy)

## Фаза 4 — Персонализация (долгосрочно)

- **Профиль навыков** — указываешь стек (Python, React, WordPress...) → LLM учитывает при анализе
- **История** — видишь тренды: какие заказы растут, какой стек востребован
- **Автоответ** — бот генерирует черновик отклика на заказ на основе твоего портфолио
- **Мульти-пользователь** — Telegram-бот для нескольких фрилансеров (каждый со своим профилем)

## Приоритеты

```
Сейчас → Фаза 1 (Telegram) → Фаза 2 (больше источников) → Фаза 3 (Vercel деплой)
  ~1 день          ~2 дня              ~3 дня                     ~2 дня
```
